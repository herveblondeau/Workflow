Deploy config — a new stone?

We agreed making the app port + SSH port configurable is legitimate (a real VPS is the "second real case"). Three decisions before designing it. Recommendations pre-selected.

How this works: each card is one decision — the recommended option is pre-selected, so agreeing is one click then Queue this answer. Use Something else for a different choice. Longer thoughts go in the Conversation panel. Then press Send to Agent. Nothing gets built yet.

1. How do we treat this?

The configurability lives in Workflow's deploy/ (stones 3/4 territory), not filigrane's nginx (stone 5).

A new stone is the textbook fit: refines stones 3/4 without rewriting them, and the journal records what revealed it.

2. What did you change in the compose port mapping?

This decides whether stone 4's loopback-only decision (127.0.0.1:8080) stays intact.

If it's just the host port, the stone is trivial and safe. If loopback changed, that's a separate design call worth surfacing.

3. One stone or two?

Two knobs: the compose published port, and the SSH port in provision.sh.

Both are the same "survive contact with a real VPS" capability and share one demo, so one stone reads cleanly.
