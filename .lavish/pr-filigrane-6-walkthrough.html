What this PR does. filigrane's prod nginx used to proxy /api/* to a bundled api:8080 backend that stone 3 deleted — so it pointed at nothing. This re-aims it at Workflow's Main.Api and injects X-Api-Key server-side, so the app runs production-style locally without the browser ever seeing the key (the prod analog of the vite dev proxy).

1frontend/nginx.conf.template3 hunks · the core
On each of the three /api locations: proxy_pass http://api:8080 → proxy_pass ${WORKFLOW_API_URL}, plus a new proxy_set_header X-Api-Key "${WORKFLOW_API_KEY}". The ${...} are resolved at container start; nginx's own $host/$remote_addr stay literal.
Entry point. This is the entire behaviour change — read it first, the rest are consequences.
What is envsubst? A tiny Unix tool (from GNU gettext) that reads text on stdin and replaces ${VAR} placeholders with the matching environment variable's value, printing the result. Here it's the template engine: the nginx image runs envsubst once at container start to turn nginx.conf.template (with ${WORKFLOW_API_URL} etc.) into a real nginx.conf with your actual values baked in. Crucially, the nginx image restricts it to only the env vars you defined, so nginx's own $host-style variables — which look the same but aren't in the environment — are left alone.
Read carefully. The design hinges on envsubst substituting only the two braced, env-defined vars and leaving nginx's runtime $vars alone. Writing $WORKFLOW_... without braces, or an env var colliding with an nginx var name, would break it. render.test.sh guards this.
Read carefully. proxy_pass ${WORKFLOW_API_URL}; renders to a literal at start, so it stays a static proxy_pass — it does not become nginx's dynamic-variable form (which needs a resolver and changes buffering/keepalive).

template vs conf. nginx.conf.template is the source in git — the old nginx.conf was renamed to it, and it holds the ${VAR} placeholders. nginx.conf is the generated output: it no longer exists in the repo; envsubst produces it fresh at /etc/nginx/nginx.conf inside each running container. Before this PR nginx.conf was copied in verbatim; now it's rendered from the template at start.
